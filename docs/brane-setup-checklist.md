# BRANE policy setup checklist

The starter README documents the `/team-policy` workbench, `GET /api/v1/policy/catalog`, `GET /api/v1/policy`, `PUT /api/v1/policy`, built-in category actions (`allow`, `placeholder`, `local`, `refuse`) and custom semantic categories. Configure built-ins in the category map and semantic rules with code, name, description, keywords, legalBasis and action. Local application checks remain mandatory.

Policy-as-code commands: `make policy-pull` saves the current `/policy` response to `policy/brane_policy.json`; `make policy-push` fetches the current version and displays a unified diff without changing BRANE; after reviewing that diff, `make policy-push-apply` sends the PUT; `make policy-check PROMPT="synthetic prompt"` runs the non-completing policy test.

## Activation evidence

For every reference, record configured BRANE policy version, enforcing component, observed BRANE verdict and corresponding test run. `make smoke` checks `GET /models`, one harmless four-field request and a closed-port failure. The separate live-only BRANE enforcement check sends a synthetic P1 schema violation and must record a denial. Local tests or the fake gateway alone do not demonstrate BRANE enforcement.
